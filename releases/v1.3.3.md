### 한국어: 개요와 패치 배경

이번 v1.3.3은 AltStore를 처음 설치하거나 새 iPhone으로 옮겨 설치할 때 다음 오류가 발생하는 **v1.3.2의 서버 호환성 문제**에 대응합니다.

> The anisette server “ani.jkcoxson.com” sent an invalid response.

10월 23일 조사 당시 해당 서버는 HTTP 200과 유효한 JSON을 반환했지만, 제공하는 인증 클라이언트 정보가 이전 Windows 방식에서 **Mac 방식**으로 바뀌어 있었습니다. 기존 패치는 Windows 정보만 허용해 정상 응답을 거부했습니다. 새 iPhone의 USB 신뢰 연결은 정상이었으며, 기기에 계정 인증을 진행하기 전 Mac의 anisette 요청만으로 같은 오류를 재현했습니다.

또한 기존 Windows 방식으로 발급된 로컬 ADI 자료는 변경된 제공자에서 `GetHeadersError / -45061`로 거부됐습니다. 이번 수정은 정상 Mac 응답을 허용하고 기존의 **-45061 발생 시 한 번 재발급하는 절차**를 다시 진행할 수 있게 합니다. 사용자 identity를 무조건 삭제하거나 계정·DNS·보안 설정을 변경하는 방식이 아닙니다.

| 오류 또는 상황 | 이번 버전에서 바뀐 점 | 확인 범위 |
| --- | --- | --- |
| **“anisette server … sent an invalid response”** | Windows 전용 판정 대신 지원하는 Windows 또는 Mac AuthKit 클라이언트 정보를 허용합니다. 빈 User-Agent와 헤더 줄바꿈은 계속 거부하며, Android 정보는 허용하지 않습니다. | 이전 Mac 요청은 ErrorResponse, 수정 후 같은 요청이 2회 연속 정상 anisette 응답으로 바뀌었습니다. |
| **서버 전환 뒤 `-45061`** | 기존 ADI가 거부된 경우 원래의 재발급 1회 경로를 이용합니다. 새 서버 응답을 일괄 거부하던 선행 조건을 고칩니다. | 기존 자료 거부와 수정 후 정상 발급·응답을 확인했습니다. 새로 추가한 무제한 재시도나 무조건 초기화가 아닙니다. |
| **Mac 방식으로 바뀐 후 iPhone 인증 정보 불일치 가능성** | Mac은 제공자가 준 client_info·User-Agent를 계속 함께 사용합니다. 동봉 iPhone 앱은 로컬 Mac 응답에 User-Agent가 없을 때, 현재 확인한 정확한 Mac descriptor에 대응하는 User-Agent를 사용합니다. | 이 보완이 포함된 앱으로 새 iPhone 설치에 성공했습니다. 설치 후 iPhone 앱 갱신은 아직 별도로 시험하지 않았습니다. |
| **기존 `-80045`, `AppleDeveloperError 3000 / HTTP 503`, HTML/plist 형식 오류** | v1.3.2의 인증 호환성·HTTP 상태 진단을 유지합니다. 이번 수정의 직접 대상은 제공자 변경 후의 invalid-response 오류입니다. | 모든 계정·네트워크의 503·-80045·-80046 또는 invalid anisette 해결을 보장하지 않습니다. |

현재 확인한 Mac client_info는 `<MacBookPro13,3> <Mac OS X;10.12.6;16G29> <com.apple.AuthKit/1 (com.apple.akd/1.0)>`, User-Agent는 `akd/1.0 CFNetwork/811.5.4 Darwin/16.7.0`입니다. **iPhone의 대체 User-Agent 처리는 이 정확한 조합에 한정**되며, 임의의 미래 제공자 변경까지 자동 대응한다고 주장하지 않습니다.

### English: overview and error-specific changes

v1.3.3 addresses a **provider compatibility failure in v1.3.2** seen when installing AltStore, including installation onto a replacement iPhone: **“The anisette server ‘ani.jkcoxson.com’ sent an invalid response.”**

On October 23 the service returned HTTP 200 and valid JSON, but its advertised client identity had changed from Windows to **Mac**. The old fetcher required Windows client_info and rejected that valid response. The replacement iPhone's trusted USB connection worked; a Mac-only anisette request reproduced the failure before Apple Account authentication.

The cached Windows ADI was also rejected with **GetHeadersError / -45061**. Accepting the supported Mac identity lets the existing single-reprovision path handle that rejection. This release does not unconditionally delete identities or change account, DNS or security settings.

| Error or condition | Change | Evidence and limit |
| --- | --- | --- |
| **Anisette server sent an invalid response** | Accept supported Windows and Mac AuthKit client descriptions while retaining empty-UA/CRLF rejection and excluding Android descriptions. | The old local request returned ErrorResponse; two requests through the repaired running Mac returned valid anisette data. |
| **Provider transition rejects cached ADI with -45061** | Allows the existing one-time reprovision mechanism to run after the provider metadata is accepted. | Old-data rejection and subsequent successful provisioning/responses were observed. No unlimited retries or blanket identity reset was added. |
| **Potential on-device User-Agent mismatch after the transition** | Mac continues to use the provider-supplied client_info and User-Agent. The companion uses the exact verified Mac descriptor/UA pair when local-server transport supplies no User-Agent. | The companion was installed successfully on the new iPhone; subsequent on-device app refresh remains untested. The mapping is not universal provider discovery. |
| **Earlier -80045, HTTP 503, or HTML/plist format errors** | Retains previous authentication compatibility and readable HTTP error reporting. | This release specifically fixes the provider-response rejection; it is not a universal fix for these errors, -80046, or invalid anisette. |

The exact Mac descriptor/UA pair is shown above. An explicitly supplied provider User-Agent takes precedence; the existing Windows fallback remains for other unmapped cases. A future provider identity change may need another compatibility update.

3. 메뉴 막대 **Install AltStore → 내 iPhone**에서 본인의 Apple 계정·2FA를 직접 입력하세요. 기본 메뉴가 동봉한 수정 IPA를 자동 선택합니다. / Choose **Install AltStore → your iPhone** and enter your own Apple Account/2FA. The normal menu selects the bundled companion automatically.

## 2. 주의 사항 / Important notes

### 한국어

- **실험용 비공식 배포**입니다. macOS 27 arm64 전용이며 Apple 공증 없이 임시 서명(ad-hoc)되어 있습니다. 차단되면 해당 앱에 대한 시스템 설정 → 개인정보 보호 및 보안 → 확인 없이 열기(Open Anyway)의 일반 절차를 따르세요.
- iPhone 앱의 최소 배포 대상은 iOS 17.4이며, 이번 실제 새 기기 설치 검증은 **iOS 27.2 + USB + 한 계정**에 한정됩니다. 사용자 설치 성공 보고 뒤 기기 조회로 **2.3.1/build6403, ProfileValidated=true**를 확인했습니다. 빌드·서명 검증과 실제 기기 결과를 구분합니다.
- **설치 후 iPhone 갱신, Remote AltServer, USB 없는 갱신, 다른 기기·계정·OS 조합은 이번 수정으로 검증하지 않았습니다.** 과거 v1.3.2의 Wi-Fi DNS 변경·LTE 성공 사례를 v1.3.3 갱신 성공으로 확대하지 않습니다.
- `-80046`, 지속되는 503, 계정 잠금, 일반 invalid anisette, 연결 끊김2002는 이번 오류와 구분해야 합니다. 이들을 모두 해결했다는 의미가 아니며 iOS hsc434 재동기화도 새로 추가하지 않았습니다.
- 외부 `ani.jkcoxson.com`에 의존하며 해당 제공자는 anisette 요청과 IP·접속 시각 등 연결 메타데이터를 처리합니다. Apple 계정 암호·2FA는 Apple에만 전송됩니다. 제공자 장애 또는 identity 변경으로 다시 호환성 문제가 생길 수 있습니다.
- 개인 계정·암호·2FA·런타임 identity·ADI·페어링 기록·개인 서명키는 배포에 포함하지 않습니다. 중첩된 기존 upstream AltBackup.ipa의 공개 upstream 프로파일은 수신자 자격 증명이나 개인 키가 아닙니다.
- 전체 대응 소스와 고정 의존성·라이선스·재빌드 스크립트를 제공합니다. 제한된 Apple crypto 구현·정적 라이브러리·복사 헤더는 제외하며 시스템 private SRP API를 어댑터로 사용합니다. 이 API는 OS 변경에 영향을 받을 수 있습니다.

### English

- **Experimental and unofficial**, macOS 27 arm64 only, ad-hoc signed and not notarized. If blocked, use the normal Privacy & Security → Open Anyway action for this app.
- The companion deployment minimum is iOS 17.4. Real-device evidence for this repair is limited to **one account, a new iPhone on iOS 27.2, and USB**. User-reported installation success was independently confirmed by the device's **2.3.1/build6403, ProfileValidated=true** metadata.
- **Post-install iPhone refresh, Remote AltServer, USB-free use and other device/account/OS combinations were not tested with this repair.** Earlier v1.3.2 cellular/DNS observations are not new v1.3.3 refresh evidence.
- This does not establish fixes for -80046, persistent503, account locks, general invalid anisette, or lost-connection2002. No new iOS hsc434 resynchronization was added.
- External ani.jkcoxson.com is an availability/privacy dependency and handles anisette requests and connection metadata. Passwords and2FA go only to Apple. Provider downtime or future identity changes can affect compatibility again.
- No account credentials, private keys, pairing records, runtime identity or ADI backup is distributed. The pre-existing nested upstream AltBackup.ipa retains its public upstream profile.
- Complete corresponding source, pinned dependencies, licenses and rebuild scripts are included. Restricted bundled Apple crypto implementations/archives/headers are excluded. The system private SRP adapter may be affected by OS updates.
